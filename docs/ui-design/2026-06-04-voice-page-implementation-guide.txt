Implementation Guide: /voice page

Использовать общие tokens, sidebar, glass panels, typography, status strip и navigation из инструкции для /agents. Ниже — только специфика страницы Voice Control.

1. Route and purpose

Route: /voice
Mobile default: / -> /voice
Desktop nav active item: Voice

Страница — компактный realtime voice control surface для Pritha. Это не полноценный чат и не замена Codex. Главная функция: старт/стоп голосовой сессии, состояние Realtime, контекст, активная задача, approval gate.

4. Voice visualization

Центр страницы — главный визуальный элемент.

Composition:

* horizontal waveform across the panel;
* glowing orb in the center;
* purple/pink/blue gradient;
* dark glass background;
* subtle pulse while listening;
* fallback without animation for reduced motion.

Use CSS/SVG. No need for Three.js here.

10. Voice page data model

export type VoiceState =
  | "idle"
  | "connecting"
  | "listening"
  | "muted"
  | "working"
  | "decision_required"
  | "error";
export type VoiceTask = {
  id: string;
  title: string;
  target: "Codex" | "Pritha" | "Child Agent";
  status: "queued" | "working" | "decision_required" | "done" | "failed";
  progress?: number;
  summary?: string;
};
export type VoiceDecision = {
  id: string;
  title: string;
  description: string;
  severity: "low" | "medium" | "high";
  status: "pending" | "approved" | "declined";
};
export type VoiceContext = {
  memoryFocus: string;
  description: string;
  activeTools: string[];
};
export type VoiceConnection = {
  realtime: "connected" | "connecting" | "disconnected" | "failed";
  server: "local" | "lan" | "tailscale" | "unavailable";
  latencyMs?: number;
  quality: "good" | "degraded" | "bad" | "unknown";

11. Mobile specifics

* hide desktop sidebar;
* show compact header with Pritha logo/title;
* status chips under header;
* voice panel first;
* current context, active task, decision cards below;
* bottom nav: Voice | Agents | Settings.

.voice-primary-button {
  min-height: 58px;
}

On mobile, controls become:

[Stop Listening]
[Mute] [Cancel]

not three equal desktop columns.

⸻

12. Safety and placeholder rules

Do not fake these as working:

real microphone access
real Realtime session
real Codex task creation
real approval application
real memory writes
real audit reports

Until backend exists:

* buttons show mock state/toast;
* labels must not imply durable action completed;
* destructive/durable actions require disabled state or explicit confirmation.

Browser must never receive OpenAI API key. Future Realtime integration must use server-issued ephemeral credentials.

⸻

13. Visual checklist

Before finishing /voice, verify:

* active sidebar item is Voice;
* main voice card dominates the page;
* orb and waveform are centered and visually close to reference;
* timer is purple and centered;
* Stop Listening button is pink-purple gradient;
* Mute and Cancel are neutral dark buttons;
* Quick Actions are small chips, not large cards;
* Conversation panel is below voice card;
* right rail order is Context → Active Task → Decision → Connection;
* approval card uses orange warning state;
* progress bar is blue/purple and shows percent;
* connection card is compact;
* page does not look like a generic chat app.
